# 実装完了後の報告・引き継ぎ手順

実装完了後は、以下の順序でフォーマットに従って出力する。

---

## 1. 実装報告フォーマット

```
## 実装報告
### 実装内容
- （何を実装したか箇条書き）

### Claude側確認済み項目
- tsc --noEmit：エラーなし / あり
- next build：成功 / 失敗

### 手動確認手順（ユーザー実施）
- （確認ステップを番号付きで記載）

### 未解決・要確認事項
- （あれば記載、なければ「なし」）
```

---

## 2. インプット項目フォーマット

実装報告の直後に提示する。

```
## インプット項目
今回の実装で理解すべき技術要素（ONBOARDING.md との対応）：

- 大項目X「〜」
  - [ ] （項目名）：（ユーザーへの投げかけ形式で問いを記載）
- 大項目Y「〜」
  - [ ] （項目名）：（ユーザーへの投げかけ形式で問いを記載）

→ 各項目について調べてアウトプットしてください。
```

**ルール：**

- インプット項目は必ず `documents/ONBOARDING.md` の大項目に対応させること
- 実装した内容に直接関係するものに絞る（詰め込まない）
- ユーザーのアウトプットに間違いがある場合は、正解を押しつけず「どう思う？」と問い返してよい

---

## 3. アウトプット確認フロー

1. ユーザーが各項目を調べ、自分の言葉でアウトプットする
2. Claude が内容の正誤・補足を確認する
3. 全項目OKになったら以下のフォーマットで完了報告する

```
## 学習完了報告
### 確認済み項目
- [x] （項目名）

### 補足・注意点
- （あれば記載、なければ「なし」）
```

---

## 4. git push とスレッド引き継ぎ

- インプット項目のすり合わせが完了したら `git push` する
- ユーザーから明示的に「プッシュして」と指示があった場合は、すり合わせ前でもその時点でプッシュしてよい

`git push` 完了後、以下のフォーマットでスレッド引き継ぎ用サマリーを出力する。

```
# スレッド引き継ぎ用サマリー
注意: プロジェクトルールはCLAUDE.md、機能仕様はdocuments/RDD.md、学習方針はdocuments/ONBOARDING.mdを必ず参照すること。

## 完了した作業
- （完了済みの作業を箇条書き）
- ※ コードや設定ファイルから読み取れる情報（技術スタック・セットアップ済み項目等）は含めない

## 実装マイルストーン（Case A: 管理機能優先）
① entities層（型定義 + Supabase API関数）
② /admin CRUD（ライブ情報管理）
③ /admin/upload（写真アップロード）
④ 公開ページ（/lives, /lives/[id], /members, /）
※ 次のタスクの先頭に「← 次のタスク」を付記すること
```
