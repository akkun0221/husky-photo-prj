# 入社までに理解すべき5つの技術要素

## 1. レンダリング戦略の適切な使い分け

- **Next.js App Router** における SSR / SSG / CSR / ISR の違いと内部的な仕組みの理解
- 各ページ（トップ、一覧、詳細など）のデータの更新頻度やユーザー固有情報の有無に基づき、最適な戦略を選択できること

## 2. アーキテクチャ設計（Feature-Sliced Design: FSD）

- フロントエンドのスケーラビリティを担保するディレクトリ構成（FSD）の理解
- `app/` (ルーティング), `widgets/` (複合UI), `features/` (ユーザーアクション), `entities/` (ドメインモデル), `shared/` (汎用UI) の依存ルール（上位から下位への片方向依存）を守ったコンポーネント分割ができること

## 3. 状態管理ライブラリの役割分担

- **サーバー状態 (Server State):** TanStack Query を用いた非同期データのフェッチとキャッシュ管理
- **クライアント状態 (Client State):** Zustand を用いたUI状態（フィルタやモーダル開閉など）の管理
- この2つの状態の性質を明確に分離し、適切に組み合わせられること

## 4. Provider設計とZustand Context Pattern

- SSR（サーバーサイドレンダリング）環境における、リクエスト間の状態汚染（Cross-Request State Pollution）リスクの理解
- グローバルなZustandストアを直接エクスポートせず、Context Providerを経由してStoreを注入する安全な設計パターンの実践

## 5. モダンインフラ・エッジ環境の活用とセキュリティ

- **Cloudflare Pages / R2:** エッジでのホスティングと、S3互換オブジェクトストレージを使った低コストな画像配信の仕組み
- **Edge Middleware:** `/admin` 配下など、特定ルートに対するサーバーサイド（エッジ）での認可チェック・アクセス制御の実装
