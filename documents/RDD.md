# ちくわフォトアルバム 要件定義書 V6

## 1. プロジェクト概要と開発フェーズ

アイドルグループ「husky」のライブ写真を管理・公開するフォトアルバムWebアプリ。
**開発フェーズ：** MVP段階として、親しいユーザー（知人のファン）を対象としたクローズドなユーザビリティテストを実施し、フィードバックを得ることを目的とする。

---

## 2. サイトマップとレンダリング戦略

CLAUDE.mdに準拠し、各ページで最適なパフォーマンスとSEO（将来用）を両立させる。

| パス                     | ページ名           | 主な機能                                                           | レンダリング戦略 |
| ------------------------ | ------------------ | ------------------------------------------------------------------ | ---------------- |
| /                        | トップページ       | 統計情報、スライドショー、タイムライン、メンバーレール             | SSG              |
| /lives                   | ライブ一覧         | 日付と会場名によるリスト表示（年別グループ）                       | SSG              |
| /lives/[id]              | ライブ詳細         | 特定ライブの写真グリッド（無限スクロール）、メンバー絞り込みボタン | SSG + CSR        |
| /members                 | メンバー別         | メンバーの写真をライブ単位でグループ化表示、無限スクロール         | SSG              |
| /login                   | ログイン           | 管理者ログインフォーム（メール/パスワード認証）                    | CSR              |
| /admin                   | 管理ダッシュボード | ライブ情報CRUD、CSV一括インポート、R2削除失敗ログ                  | SSR + RBAC       |
| /admin/upload            | アップロード       | ドラッグ&ドロップによる写真一括アップロード（Canvas圧縮）          | SSR + CSR + RBAC |
| /admin/lives/[id]/photos | ライブ写真管理     | 特定ライブの写真編集・メンバー割り当て・削除                       | SSR + RBAC       |

---

## 3. ページ別詳細仕様

### 3.1 トップページ（/）

- **統計情報（OpeningMonument）:** 公演数・写真数・メンバー数を表示。
- **スライドショー（PhotoSlideshow）:** 最新5ライブの写真をダブルバッファでクロスフェード表示（3.6秒ごとに切り替え）。
- **タイムライン（MemorialClient）:** 全ライブを時系列に一覧表示。
  - 方向トグル（2022→2026 / 2026→2022）を URL searchParams で管理。
  - 年別アンカー（#y2022 など）でジャンプナビ。
  - モバイル：縦並び / デスクトップ：3列グリッド。
- **メンバーレール（MembersRail）:** メンバー5人のカードを並列表示。各カードからメンバー別写真フィルターへ遷移。

### 3.2 ライブ一覧（/lives）

- **年別グループ化:** 2022〜2026の年ごとにライブをグループ化。
- **表示内容:** 曜日・日付・会場名・タイトルを一覧表示。
- **写真なし非表示:** 写真が1枚も登録されていないライブは表示しない。
- 各ライブのリンクから `/lives/[id]` へ遷移。

### 3.3 ライブ詳細（/lives/[id]）

- **ビルド時生成:** `generateStaticParams()` で全ライブIDの静的ページをビルド時に事前生成。動的メタデータ（OGタグ）も生成。
- **ヒーローセクション:** 日付・曜日・会場名・タイトル・説明を表示。
- **絞り込み機能:** メンバー選択をボタン形式で配置（URL searchParams: `?member=id`）。
  - 選択肢：全て（デフォルト）、ちくわ、空良、しぅく、びゃくや、のどか、全体。
  - 「全て」は `live_id` に紐づく全写真を表示。「全体」は複数人写りのみを表示。
- **表示形式:** 無限スクロール対応の写真フィード（24枚ずつ取得）。仮想スクロール（TanStack React Virtual）でDOM数を削減。

### 3.4 メンバー別ページ（/members）

- **絞り込み:** メンバー選択をボタン形式で配置（URL searchParams: `?member=id`）。
- **表示形式:** ライブ単位でグループ化した写真を表示。グループ内は詰め込みレイアウト（Justified Layout）。
- **無限スクロール:** `useInfiniteQuery` を使用し、スクロールに応じて追加読み込み。

### 3.5 管理ダッシュボード（/admin）

- **ライブ一覧テーブル（LiveList）:** 初期10件 + 展開ボタン。
  - 新規追加ダイアログ / 編集ダイアログ / 削除確認。
  - 各ライブの写真管理リンク（`/admin/lives/[id]/photos`）。
- **CSV一括インポート（ImportLivesDialog）:** CSVファイルからライブ情報を一括登録。
- **R2削除失敗ログ:** R2オブジェクト削除に失敗したレコードをテーブルで表示。

### 3.6 アップロード（/admin/upload）

- **ドラッグ&ドロップ:** 複数ファイル選択対応。プレビュー表示。
- **メンバー設定:** 各ファイルに個別設定 / チェック済みに一括設定。
- **画像処理（Canvas API）:**
  - 最大辺 2000px にリサイズ。
  - 二分探索（最大3回）で 500〜800KB に正規化。WebP形式で出力。
  - サムネイル：最大辺 400px、品質 0.85 固定のWebP。
- **アップロード:** 最大3並列でR2へPUT。確認モーダルで漏れチェック。進捗表示（完了/エラー数）。

### 3.7 ライブ写真管理（/admin/lives/[id]/photos）

- **グリッド表示（AdminPhotoGrid）:** 複数選択対応のチェックボックス付きグリッド。
- **メンバー割り当て:** 選択した写真のメンバーを一括変更。
- **削除:** 物理削除（DB + R2）。R2削除失敗時はログを記録。

## 4. ディレクトリ構成（Feature-Sliced Design）

CLAUDE.mdの依存ルール（features → entities → shared）を厳守する。

- **app/:** ルーティング定義、各ページのLayout/Pageコンポーネント。
- **widgets/:** LiveCalendar, PhotoGrid, Header 等、複数のfeatures/entitiesを組み合わせたUIブロック。
- **features/:** FilterPhotos, UploadPhoto, AuthAdmin 等、ユーザーの行動（Action）に基づくロジック。
- **entities/:** Photo, Live, Member の型定義、API通信、状態（Zustand Store）の定義。
- **shared/:** Button, Card (Shadcn UI), 汎用ユーティリティ。

---

## 5. データモデル（概要）

```
members テーブル
  id (uuid, PK), name (text), color (text)
  ※「全体」も1レコードとして登録済み（計6レコード）

lives テーブル
  id (uuid, PK), date (date), venue (text), title (text),
  description (text), thumbnail_photo_id (uuid)

photos テーブル
  id (uuid, PK), live_id (uuid, FK → lives),
  member_id (uuid, FK → members), r2_url (text),
  thumbnail_url (text), width (integer | null), height (integer | null)
  ※ thumbnail_url はMVPでは r2_url と同値でよい
  ※ width/height は仮想スクロール・Justified Layout のアスペクト比計算に使用
```

---

## 6. 技術的制約とルール

- **状態管理:** Zustand Context Patternを必須とし、ページコンポーネントでProviderをラップする。
- **画像処理:** Canvas APIを用いてフロント側で圧縮（目標500KB〜800KB）。
- **セキュリティ:** Edge Middlewareによる /admin 保護。環境変数はサーバーサイドでのみ使用。
- **仮想スクロール:** TanStack React Virtual を使用し、大量写真表示時のDOM数を削減する。
- **無限スクロール:** `/lives/[id]` および `/members` で `useInfiniteQuery` を使用。
